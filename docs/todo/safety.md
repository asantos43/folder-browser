## File safety triage: what is this file, and is it safe to open? (priority Next, size M)
- [ ] **Properties ▸ Safety** (and a bar over a file the triage found something in): all **offline**, nothing executed, read through the sandboxed readers (see "Metadata of media files in Properties"): **the real type against the name** (magic bytes against the extension: an `.exe` called `.pdf`; a double extension; a right-to-left override in the name); **Office files with macros** (VBA, `vbaProject.bin`, Excel 4 macros, external links and templates, embedded objects) and **PDFs with JavaScript, launch actions, embedded files and form submissions**; **archives** with names that leave the folder, a ratio that says bomb, a nested depth, an encrypted entry, an executable inside; **scripts and shortcuts** (`.lnk`, `.desktop`, `.scr`, `.jar`, `.hta`); **text with hidden or dangerous characters** (zero-width, bidirectional controls: see below)
- [ ] The result is **a list of findings with a plain-words explanation and a level** (nothing found is *not* "safe": the panel says what was looked at and what was not); the viewers that exist already draw files in isolated frames, so **Open Safely** is what a click does, and **Open With…** on a risky file asks first
- [ ] The rules are **data** (a list of checks with a name, a test and an explanation), so they can be updated by an **extension** (level 0, signed) without a release; no hashes of known malware and no network
- [ ] **Hidden and dangerous characters in the text editor**: a setting (on by default) that **marks** zero-width characters, bidirectional controls ("Trojan Source"), non-breaking spaces and look-alike letters in source, with a status bar count and **Remove Them**
- [ ] Performance and tests: the triage reads only the first and last blocks and the central directory (never a whole big file), runs in the worker with a time limit, is cancelled when the properties close; hostile fixtures for each check (a macro-bearing `.docx` made by the fixture builder, a PDF with an action, a ZIP bomb, an RLO name); a **false positive budget** on a corpus of ordinary files

## Share safely: show and remove the hidden data (priority Next, size M)
- [ ] **Properties ▸ Hidden data** and a **Share Safely…** command for a file or the marked files: it lists **what the file carries that the person may not know** (the GPS position and camera of a photo; the author, last-modified-by, revisions, comments, tracked changes and hidden text of an Office file; the title, author, creator and XMP of a PDF; ZIP comments and the dates and names of its entries; file times) and offers **Remove**, as a copy or in place, with the Local History keeping the original
- [ ] The removal is **lossless for the content**: JPEG, PNG and WebP metadata is replaced without recompressing (see "Metadata (EXIF)"); an Office file or an OpenDocument is rewritten by `core/archive/edit.ts` with the properties parts emptied; a PDF's information and metadata are rewritten by an incremental or a full save; a ZIP's comment and extra fields are cleared
- [ ] It **reuses**: the EXIF reader and writer, the shared metadata reader, the PDF writer of the PDF plan and the safe write of ZIPs; nothing here is a new engine, it is a **guided path** over them (the reason it is **Next**: it depends on the first metadata work)
- [ ] Performance and tests: a batch of 1,000 photos is processed in a worker with progress and cancel; tests that the pixels or the text are **unchanged** (byte-for-byte for the image data) and that **no tag of the removed kinds is left** (read back with an independent reader)

## Redaction that really removes (priority Later, size L)
- [ ] **PDF**: select an area or a text and **Redact**: the content under it (the text objects, the image pixels, the annotations) is **removed from the file**, not covered by a box, and the result is checked by extracting its text; the metadata can be removed in the same step; saved as a **new PDF** by default (the Local History keeps the original)
- [ ] **Image**: a **redaction tool** in the editor (a solid box, pixelate, blur) that writes the pixels and **drops the metadata and the thumbnail**; **text**: **Redact Selection** (blocks, in "Text tools") and a find-and-redact for patterns (a card or tax number, an e-mail), reviewed before it is applied
- [ ] A **preview of what the file will look like and what text it will still contain** before saving, and a warning that a **screenshot of a box over text is not redaction**
- [ ] Tests: the PDF's extracted text, its raw bytes and its object streams must not contain the redacted string (a test that **fails if the string is found anywhere in the file**), and a budget on a 200-page PDF

## Inspect-only mode and a record of what the application changed (priority Next, size S to M)
- [ ] **Inspect Only** (a toggle in the title bar, a setting and a command-line flag): every operation that writes is **refused at the one place all writes go through** (the registry and `core/fs/ops.ts`), the interface shows what is disabled and why, and drafts are not written; for looking at evidence, a shared folder or a file that must not be touched; a test that **no write path is reachable** in this mode
- [ ] **Activity log**: a local, append-only list of **every change the application made** (what, when, the root and path, before and after sizes and hashes, the Local History version) that the user can **read, search and export**; it never leaves the computer, has a size limit, and is the base of the "undo the last operation" item
- [ ] Performance and tests: the log is written in a batch and does not slow a save; it is bounded (rotated by size and age); a test that every operation of `ops.ts` and the ZIP editor leaves one entry

## Repair damaged files (priority Later, size M)
- [ ] **A ZIP with a damaged directory**: rebuild the list by scanning the **local headers**, show what could be read, mark what cannot, and **Extract What Is Readable** (never writing over the damaged file); **a PDF** that pdf.js reads with errors is shown with what it has and a notice of what was skipped; **a truncated picture** shows the part that decoded; **a damaged text** is shown with the bytes that are not valid UTF-8 marked
- [ ] Performance and tests: the scan streams, is cancellable and bounded; fixtures made by cutting and corrupting good files; the output states plainly what was lost
