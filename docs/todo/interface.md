- [ ] **Remember where you were in a file, and the zoom and place of a picture** (priority Next, size S to M): coming **back to a file** (a tab that was closed and opened again, in the same session or after a restart) puts you **where you were**: a text at the same line and caret, a picture at the same zoom and place, a PDF at the same page and zoom. A tab that stays open already keeps its state (the editor's buffer, the zoom of the tab); this is for the **file**, not for the tab, and it is kept in **a short list that is bounded**, so it costs almost nothing.
  - **What is remembered, by kind**: **text** (the top line shown and the offset into it, the caret and the selection's end, folded regions later; by line and column and not by pixel, so it survives a change of font, zoom or window size); **picture** (the **zoom mode** (fit, actual size, or a factor) and the **centre of the view as a fraction of the picture**, so it survives a resize of the window; and the choice of the checker or dark background); **PDF** (the page, the position inside it and the zoom mode); **formatted Markdown, HTML preview, documents, the page of a snapshot** (the scroll as a fraction and the zoom); **table** (the first row shown, the sort and filter, the column); **hex** (the offset); **video and sound** (the time, kept only past a few minutes: the *resume where it stopped* of `docs/todo/media.md`, one mechanism); **diff** (the scroll).
  - **Snapshots (`.wsnp`) are supported too**: the **page of a snapshot** and **each file opened from it** come back where they were. **What**: for the page, the **scroll position** (horizontal and vertical, as **fractions of the page's size** so it survives a resize and a change of zoom), the **zoom of the tab**, and the page's own `#anchor` if the user was at one; for a file of the snapshot (a text, a picture, a PDF) the same as for a file of a folder (its key is the snapshot plus the entry's path); for the **Metadata tab** its scroll. **How it is read**: the page lives in a **sandboxed frame in another process**, so the position is reported by the **frame script** the application injects (`core/frameScript.ts`, the same that carries the zoom keys and the wheel): a throttled message (at most a few a second, and only when the scroll changed) with **two numbers**, nothing else, which the interface keeps in memory and writes with the rest of the list; a page can only lie about its own scroll, and the values are **clamped numbers**, never text. **How it is restored**: after the page's `load`, the frame script scrolls to the fraction, **and again once the page settles** (images that have no size yet, fonts and lazy content change the height): it **stops as soon as the user scrolls**, and never fights an `#anchor` or a link that was asked for. **The identity**: a snapshot is **immutable and has a hash of its manifest**, so its key is that **hash** (the check already computes it) and not its path or its modified time: **a renamed, moved or copied `.wsnp` keeps its place**, and a *different* snapshot with the same name does not inherit another's; a snapshot **converted from a PageKeep ZIP** is keyed by the ZIP's own hash. **Tests**: the frame script's report (throttled, clamped, only on change); restoring a page that grows after load (a late image); the user's own scroll cancelling the restore; the hash key surviving a rename and a move, and two snapshots not sharing a key; the zoom restored; a file of the snapshot restored like any file; an end-to-end spec with a **fixture snapshot taller than the window**: scroll, zoom, close, reopen (also after renaming the file), restart.
  - **The list**: an LRU of **200 files** (a setting), each entry the **file's identity** (the root's path and the path inside it; for an entry of a ZIP the ZIP's path then `!/` and the entry; for a snapshot its file and the entry) with its **size and modified time**, the kind, a few numbers and the time of the last use; about 100 bytes each, **20 KB in all**, older entries dropped first, and entries older than a limit (a year) dropped at start. It is kept in the application's own folder (`userData/view-state.json`), written **at most every few seconds and when the tab closes or the window quits**, never on each scroll (the scroll updates the in-memory entry only).
  - **Rules**: **a change of file is not a place**: if the size or time changed, a text keeps its line (clamped to the new length), a picture whose dimensions changed goes back to *fit*; a **rename or a move** carries the entry to the new path (the `path-changed` of the tabs and of the file operations), a **delete** drops it; **what the user asks for wins**: opening a file at a line (a search result, a link, Go to Line, a command-line `path:line`), or a `#anchor`, **overrides** the saved place; the restore **never steals the focus** and runs **after the content is drawn**; a file that is **not a normal file** (a snapshot page, a diff of two files, a new text) has no entry, or its own rule.
  - **Settings for all this** are written in `docs/todo/settings.md` ("Position and zoom of files"): the switch, the size and age of the list, the kinds, the caret, the pictures' zoom choice, the folders to leave out, and Clear.
  - **Privacy and control**: the list holds **paths**, so it is **local only**, listed in the privacy text, with a **switch** in Settings (**Remember the position and zoom of files**, on by default), the **size of the list**, and **Clear** (with what it removes and the size); **Inspect Only** mode and the "private" use of a folder (a setting to exclude a root) do not write it.
  - **Pictures in particular**: besides the per-picture memory, a setting **Keep the last zoom for all pictures** (a picture opens at the zoom of the previous one) for the person who looks at a folder of screenshots at 100 % and does not want *fit* each time; the default stays **per picture**.
  - **Performance** (the rule at the top): reads are an **O(1) lookup in a map held in memory** (the file is read once at start, a few KB), the scroll handlers only set two numbers, writing is **debounced and atomic**, restoring a text position is **one scroll** after the first draw (no second layout), and the list is **bounded** in count and size.
  - **Tests**: the store as a pure module (LRU, the bound, the age limit, a rename and a delete, a corrupt or too-new file ignored, an entry with a changed size); each viewer's restore after the tab is closed and reopened (the editor's line and caret, the picture's zoom and centre after a **window resize**, the PDF's page); that an explicit **line** overrides; that the setting off stores nothing and Clear empties it; a budget (a 50,000-line file restores in one frame); and an end-to-end spec: scroll a long text and a picture, close the tabs, reopen, check the positions, restart, check again.
  - **Decisions**: **kept across restarts** (the recommendation: yes) or only for the session; the **default size of the list** (200); whether the **caret** is restored as well as the scroll (yes); whether the picture's **per-picture** or **last zoom for all** is the default (per picture); and which kinds are in the first version (the recommendation: **text, pictures and PDF** first; the others follow).

## Development process: reviews of the code by plugins (priority Now, size S)
**Light use**: the user's weekly limit is finite, so nothing here runs unless the user asks for it in that message; the rule and the cheap way to work are in `CLAUDE.md`, "Light use".
Two plugins of the official Anthropic marketplace (`claude-plugins-official`) are installed for the user (`claude plugin install … --scope user`): **`claude-security`** (`/claude-security`: a scan of the whole repository or of **this branch's changes** by a team of agents that map the code, hunt for flaws and **try to disprove every finding** before it is reported; a report with severity and confidence, a SARIF file and, if asked, patches to apply by hand; it asks once to confirm its cost) and **`pr-review-toolkit`** (`/pr-review-toolkit:review-pr`: agents for code quality, **silent failures and error handling**, the **tests** a change needs, the **design of types**, comments, and **simplification**). Both run in the session, their agents in parallel, after `/reload-plugins` or in a new session. Reviewed before they were installed: neither has a daemon or network calls of its own; the hooks of `claude-security` only show a banner, count its own runs and suggest a scan after a push; **`security-guidance`** (hooks on every edit, a review of the diff by the model at every turn and on every commit, an SDK installed in a virtual environment) was **left out** on purpose because it spends tokens in the background all the time: it can be added if wanted.
- [ ] **When to run what**: `pr-review-toolkit` on **every pull request that changes application code**, before the merge; `claude-security` on **scan changes at high effort** for every pull request that touches **a parser, a writer, an IPC channel, a path of the file system, a process that is started, or the CSP**, and on the **whole repository** before each release; the findings are fixed in the same pull request or written here as items; the `CLAUDE-SECURITY-*` folders are never committed (they carry their own `.gitignore`); the cost is stated to the user before a scan is run
- [ ] The first **whole-repository scan** (effort `high`) of the code as it is today, and its report read and sorted into fixes and items here
- [ ] A line in `CLAUDE.md` (done) and in `CONTRIBUTING.md` for the people who contribute: what the reviews are and that the maintainer runs them
- [ ] Quality measures to add when a tool is chosen: coverage of the unit tests reported (not as a gate), a check of the size of the installer and of the start-up time on each release (the performance rule's "cost of arriving"), and `npm audit` of the dependencies before a release
