# TODO: Files that understand their content (file intelligence)

Part of the plan in [`TODO.md`](../../TODO.md) (the index, the performance rule and the roadmap). Open work of this area; what was delivered is in [`history.md`](history.md).

Idea, decided in principle, after 0.1.3: **the pillar of the positioning** ("the file manager that understands your files", see `README.md` and `docs/todo/positioning.md`). The aim is the small task done in place: open a Dockerfile, a Kubernetes manifest, a CI workflow, a `docker-compose.yml`, a Terraform file, an `.env`, an nginx or systemd file, a certificate or a JWT, and **see at once what it is, what is wrong with it, and what it says**, with no other program. The core provides the shell and the framework; the **types are taught by extensions** ("file intelligence packs", see `docs/todo/extension-first.md`), first-party and community.

## The framework (priority Next, size M to L; the foundation of the packs)
- [ ] **Detecting what a file is**, beyond the extension: by **name and path** (`Dockerfile`, `docker-compose*.y*ml`, `.github/workflows/*.yml`, `Chart.yaml`, `package.json`, `nginx.conf`, `*.service`, `crontab`), by **content** (a YAML with `apiVersion` and `kind` is a Kubernetes manifest; several documents in one file; a `---` front matter; a shebang; a PEM block; three dot-separated base64url parts are a JWT) and by **magic bytes**; a detector is **data plus a small function** that an extension can contribute, tested on hand-made files; the type is shown in the tab and the status bar and can be **changed by hand** (the language picker exists)
- [ ] **The Problems panel**: diagnostics with a **severity, a line and column, a message in plain words and, where possible, a quick fix**, shown as marks in the editor (CodeMirror's lint), a **list** that can be filtered and jumped through (`F8`), a count in the status bar, and an entry per file open in the tab strip; it works for **any** source of diagnostics (a schema, a linter in WebAssembly, an external tool): one panel, many sources
- [ ] **Validation against a schema** for JSON and YAML: **JSON Schema** checked in a **worker** (Ajv or the engine the spike picks), with the catalog of **SchemaStore** (Apache-2.0) **bundled offline** and mapped by file name (hundreds of config files: `package.json`, `tsconfig`, workflows, compose, and so on) and the **Kubernetes schemas** per version of the API; hover and completion from the schema; the panel says **which schema and which version** was used and what was **not** checked ("valid" is never promised to mean "it will work")
- [ ] **Format** (exists for some types; extend to Dockerfile, YAML, TOML, HCL where a small formatter exists), an **outline** per type (the resources of a multi-document YAML, the stages and instructions of a Dockerfile, the jobs and steps of a workflow, the sections of an INI) in the side bar or a breadcrumb, and **Convert** between JSON, YAML, TOML and `.env` (keeping comments where the format allows, and **saying what is lost**)
- [ ] **Inspect** (small, pure, high value; each also a hover on the selected text): decode a **certificate** (PEM or DER: subject, issuer, validity with a warning near the end, SANs, key type and size, fingerprints), a **JWT** (header and payload decoded, the dates in words; **never** claiming it is valid without a key), **base64**, **URL** and **percent encoding**, a **UUID**, a **Unix time**, a **cron** line (in words and the next runs), a **semver** range, a **CIDR** (the range and the number of addresses), a **permission** such as `chmod 755`, and a **regular expression** with a test box
- [ ] **Run the local tools, opt-in**: when the computer has them, a **Check with…** that runs `kubectl apply --dry-run=client`, `docker compose config`, `docker build --check`, `terraform validate`, `hadolint`, `shellcheck`, `yamllint` and the like on the file and **turns their output into problems in the same panel**; each is an **Open With-style entry** (a program, arguments, a timeout, the working folder), **started without a shell**, never run by itself, **confirmed once** and read-only by default; a level 2 extension (see `docs/todo/extensions.md`) when it needs more than that
- [ ] **Secrets**: a scan of the open file for keys and tokens (private keys, cloud and API keys, passwords in a URL, high-entropy strings in an `.env`), **marked in the editor and listed in the panel**, with a warning before **Share Safely** or a copy out (see `docs/todo/safety.md`); the rules are data, an extension can add some, and they never leave the computer
- [ ] **Quick actions** in the right-click menu and the palette by type (**Validate**, **Format**, **Show Outline**, **Decode**, **Check with…**), so that the task is **one key away** from opening the file
- [ ] **Performance** (the rule at the top; the point of the pillar is that it is *quick*): the type is known in a few milliseconds, diagnostics of a 1 MB YAML appear in **under 200 ms** and never block typing (worker, debounced, cancelled when the text changes again, only the changed document of a multi-document file when possible), schemas and WebAssembly engines are **loaded on first use**, the bundled catalog is an **index** read on demand (not parsed at start), and the cost on the installer is stated
- [ ] **Tests**: detection on a corpus of real-shaped files (and ambiguous ones); each diagnostic with a golden file; the schema validation against the Kubernetes and workflow samples (a valid one, an unknown field, a wrong type, a missing required field); each inspector on known vectors (a certificate with a known fingerprint, a JWT, the cron next runs against a fixed clock); the external tools through a **made-up program** that prints known output; an end-to-end spec: open a manifest with an error, see the mark, the panel and the quick fix

## The packs (first-party extensions; priority Next for the first, Later for the rest)
Each is an extension that **contributes detectors, schemas, outlines, inspectors and tool entries**; level 1 where it only computes, level 2 where it starts a program. They can be **built in** or **official** (see `docs/todo/extension-first.md`).
- [ ] **DevOps pack** (the first, and the demonstration): Dockerfile (parse, instruction checks, best practices such as pinned tags and `apt-get` cleanups, an outline of stages), docker-compose, **Kubernetes** (schema per API version, resources and their references, a multi-document outline, common mistakes such as a selector that matches no label or a missing resource limit), **Helm** values, **GitHub Actions** and GitLab CI (schema, unknown actions, an outline of jobs), **Terraform** and HCL (syntax and an outline), Ansible, nginx, systemd units, crontab, `.env`
- [ ] **Web and data pack**: OpenAPI (schema, an outline of paths), `package.json` and lockfiles (a summary of dependencies), tsconfig, ESLint, GraphQL, SQL (syntax per dialect), XML with XSD, Markdown front matter
- [ ] **Security and crypto pack**: certificates and keys (PEM, DER, PKCS#12 with a password, SSH keys and `known_hosts`, GPG armour), JWT and JWK, hashes, a decoder of common encodings, a **secrets** rule set, and the **file safety triage** (see `docs/todo/safety.md`)
- [ ] **Logs pack**: JSON lines, syslog, nginx and Apache access logs, a **filter by level, time and text**, a **follow** mode (`tail -f`), and a histogram of lines over time
- [ ] **A community path**: the guide for authors (see "Extensions", phase 5) gets a recipe for each of these (a detector, a schema, an inspector, a tool entry), so that a person can add *their* type in an afternoon
- Not planned: a debugger, a language server for every language (the text editor stays light; hand a project to an IDE), and running a file's contents (a script, a manifest) on the user's behalf

## Decisions to make
- **Order**: the framework (detection, the Problems panel, schema validation) with the **DevOps pack** as its proof, then the inspectors; or the inspectors first (small and quick to show)?
- **SchemaStore bundled offline** (the recommendation: size to measure, a few MB, updated at each release) or fetched on request (it would need the network: against the promise)
- **The validation engine**: Ajv in a worker (JavaScript), or WebAssembly engines (`kubeconform`, `hadolint` and `shellcheck` have WebAssembly or Go builds: heavier but the real tools)
- **How far external tools go**: only a list the user confirms (the recommendation), or detecting and offering them automatically
- **Resident mode for a fast start** (a hidden window kept ready, opt-in, with its memory cost) so that opening a file from the file manager costs about what a small editor does: part of this pillar's promise, its own item in `docs/todo/positioning.md`
