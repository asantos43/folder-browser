## Settings: more control over the application (after 0.1.3; priority Now for the framework, Next for most of the options)
Today **Settings** has the colour theme, the language, the colour of the divider line, reopening what was open, keeping unsaved changes, showing hidden files, word wrap and formatting of source, and the privacy note. Many more behaviours exist in the code as constants or as buttons of a toolbar with no place to be set once for all (the limits for text, logs and bytes, the diff layout, the SVG view, the Markdown width, the sort, the shortcuts, the confirmations, what a click does). The aim: **a page of settings that grows by adding one declaration per option**, and then the options themselves. Every option has a default that is today's behaviour, so nothing changes until it is changed.

The framework (priority Now, size M)
- [ ] A **registry of settings** (`src/state/settingsRegistry.ts`, plain data, tested): each setting is declared **once** with an id, a type (boolean, a choice among values, a number with a minimum and a maximum, a string, a colour, a list of strings), a default, a category, the keys of its label and description in English and Brazilian Portuguese, keywords for the search, whether it needs a **restart**, whether it may also be set **per folder** (later), and what applies it. The **Settings page is made from the registry** (no hand-written row per option), so a new option is one declaration and its two texts
- [ ] **Categories on the left** (Appearance, Editor, Files and Tree, Tabs and Layout, Search and Diff, Media, Images and PDF, Keyboard, Privacy and Storage, Performance, System, Advanced), the **search box** (it exists) matching name, description and keywords in the language in use, a **modified** mark on what is not the default with **Reset** on each row and **Reset Section**, a filter **Show Only Modified**, descriptions in plain words with the default and the range, and a note on the row that needs a restart (with a **Restart Now** button)
- [ ] **Stored in a file the application owns** (`settings.json` in the user's data folder, written atomically by the main process through a validated IPC channel; today it is the page's local storage, which the main process cannot read and a person cannot edit or back up); the file is read **once at start** (small and synchronous, so the window can use it before it is drawn: the window size, the hardware acceleration and the watcher are read in the main process), a **version** number and a migration from the old local storage keys on first start, unknown keys kept and invalid values ignored one by one with a notice
- [ ] **Open Settings (JSON)** in the Settings page's toolbar: opens `settings.json` in the text editor, with the registry as a **JSON Schema** for completion, hover descriptions and validation, and **applies a saved change at once** (a bad value is refused in words, the rest kept); **Export…** and **Import…** (a `.json` chosen by the user: only known keys are taken, each checked against its type and range, nothing is run, a summary of what changed is shown before it is applied); **Reset All** after a confirmation that names what is lost
- [ ] **Extensions contribute settings** to the registry (see "Extensions", phase 1): the same declaration, validation, search, reset, export and import, under **Extensions ▸ <name>**, listed without running the extension's code
- [ ] **Every change applies live** where it can (a hook per setting, so a change re-renders only what uses it, never the whole window) and says **restart required** where it cannot; the settings are the **only** place for a default (the toolbars' buttons keep working as shortcuts to the same value)
- [ ] A **reference of every setting** made by a script from the registry (`docs/SETTINGS.md` and `docs/SETTINGS.pt-BR.md`, with the guide linking to them), so the documentation cannot drift from the code
- [ ] Tests: every setting's default passes its own validator; every label, description and choice has a key in **both languages** (the existing parity test extends to the registry); the page lists every setting once and finds it by a word of its description; reset, reset section and show-only-modified; import of a file with good, bad, unknown and out-of-range values; the migration from the old keys; a hand edit of the JSON applied live; a restart-required setting; and an end-to-end spec (change an option, see its effect, restart, see it kept). A budget: the page opens and filters in a frame with 200 settings, and reading the file adds nothing measurable to the start

The options (each is one declaration once the framework is there; the ones named **Next** are the first batch)
- **Appearance**: colour theme and divider colour (there); **UI font and size**; **editor font family, size, line height and ligatures** (Next); **density of the tree** (compact, normal, relaxed rows); **custom colours** for the selection, the active line and the diff (the `--wsnp-*` tokens, with a reset); show or hide the **status bar**, the **activity bar** and the **breadcrumbs**; **reduce motion**; **high contrast** (see "Quality of the product")
- **Editor** (Next): word wrap and format source (there); **tab size**, **spaces or tabs**, **detect the indentation of a file**, **auto-indent**, **auto-close brackets and quotes**, **line numbers**, **the minimap** (show or hide, its size, characters or blocks, the side and when the slider shows: see "A minimap" in `docs/todo/text.md`), **highlight the active line**, **bracket matching**, **rulers**, **cursor style and blink**; **on save: trim trailing whitespace, insert a final newline**, **default line ending and encoding of a new file** (and the byte order mark); **auto save** (off, after a delay, when the focus leaves the editor); **a language for a file type** (a list: `*.conf` as INI, `*.tpl` as HTML); **spell check** off or on
- **Files and the tree** (Next): show hidden (there) and the sort (in the menu today): **folders first**, **natural order of numbers**, **case sensitivity**; **what a click does** (one click opens a preview tab, as now, or only selects; double click to keep), **preview tabs on or off**; **confirm before moving a file by drag**, **confirm before moving to the trash**, **Delete goes to the trash or asks for permanent**; **names to hide from the tree, Go to File and the searches** (a list of globs: `node_modules`, `.git`, `*.pyc`: a `files.exclude`), **the folder shown at start** (the last one, the Home folder, or none), **how many recent items**, file icons on or off, **size and date columns** (see the open item)
- **Tabs and layout**: **where a new tab opens** (beside the current one, as now, or at the end), the **close button** always shown or on hover, **side bar side** (left or right) and its width, **the split's default direction**, **ask before closing a tab with changes** when changes are not kept, the **tabs' limit**
- **Search, find and diff** (Next for the diff): the diff's layout and collapse (there) plus **ignore whitespace**, **ignore case**, **how many lines of context are kept around a change**, **word-level marks on or off**, **compare line endings**; Find's **default options** (case, whole word, regular expression, wrap around) and the **size of its history**
- **Media**: **autoplay on open**, **autoplay of the next**, **default volume** and **speed**, **loop** by default, **remember the volume**, the **media keys** on or off, **resume where it stopped** (see "Video" and "Playlists"), subtitles' size and colour, **preferred audio and subtitle languages**, and for a playlist whether a track that is not found is skipped or stops the play
- **Images, PDF and documents**: the **default zoom** (fit or actual size) of a picture and of a PDF, the **background** behind a picture (checker, dark, light), **smooth or pixelated** when enlarged, SVG as a picture or as source (the toolbar's value, now stored), PDF **page layout** and **dark mode** (invert the page), CSV/TSV **delimiter**, **header row** and **how many rows are drawn at once**
- **Limits the code has as constants** (with a safe range, a note and an explanation that a higher limit costs speed and memory, per the performance rule): the **biggest text** opened for editing (5 MB), the **biggest log** (32 MB), the **biggest file the hex view edits** (16 MiB), the **biggest picture and PDF** shown, the **most entries of a ZIP** edited, the **most files in Go to File**
- **Keyboard** (Next): a **list of every command with its shortcut**, **rebinding** with conflicts shown and a reset per row and for all (the table of `core/shortcuts.ts` becomes the default of a user's table: the main process reads the user's table too, so a key still works with a snapshot's frame in front), a **scheme** to start from (**VS Code**, as now; **Notepad++**; **Windows Explorer**) which settles the open decision of "Text tools" about keys, and **import and export** of the keys; the commands of "Text tools" and the others appear in the list as they are made
- **Privacy and storage** (Next): the **Open With…** list (the programs offered and a **custom command** with a name, a program and arguments with `{file}`, confirmed once and never run through a shell), **links in a document open in** the default browser **after asking** (always ask, ask once per site, never), **web addresses in a playlist** (never, the recommendation, or opt in), **update check** (off, see "Quality of the product"), **how long drafts are kept**, the **limits of Local History** (size, versions, age), the **size of the thumbnail cache**, and **Clear…** buttons (drafts, history, thumbnails, recent files, favourites, the saved session) each with what it will remove and the size it frees; the privacy note says what is kept and where
- **Performance**: **how many workers** the search, the checksums and the thumbnails may use, the **sizes of the caches**, thumbnails on or off, the **watcher** on or off, **hardware acceleration** (restart), and a **preset** (Balanced, Light on memory, Fast on big folders) that sets several of them
- **System**: the **file types** the application is registered for (`.wsnp`, `.zip`, `.m3u8`: a switch each, where the system allows it), **one window or many** (open files in the one that exists), **remember the size and place of the window**, **start maximised**, **always on top**, **language**: the system's (as now) or a fixed one
- **Advanced**: **per-folder settings** (an override kept in the application's own folder by the root's path, never a file in the user's folder unless asked), **profiles** (a named set that can be switched), a **developer mode** that shows the logs and the performance counters of the performance rule

Notes
- Priority of the batches: the **framework** first (it makes every other option cheap); then the **Next** options (editor, tree and tabs, diff, keys, limits, privacy and storage); then media, images and PDF as those features arrive; then system, per-folder and profiles.
- A setting that changes **safety** (a custom Open With command, opening links, web addresses, the limits) is never applied from an imported file without the confirmation of the person, and its default is the safe one.
- **No sync** between computers (nothing leaves the computer); the file can be copied by hand.
- Performance: the registry is data read once; a change notifies only the components that read that setting; writes are debounced and atomic; the page is a list of rows that draws as the user scrolls; and each new option follows the rule at the top (a limit has a safe range and a budget).
