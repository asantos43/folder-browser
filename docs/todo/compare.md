# TODO: Compare more than text

Part of the plan in [`TODO.md`](../../TODO.md) (the index, the performance rule and the roadmap). Open work of this area; what was delivered is in [`history.md`](history.md).

Idea, decided in principle, after 0.1.3. **Comparing is the third scenario of the positioning**; today only two text files can be compared (`DiffView`, `@codemirror/merge`). The paid tool that is the reference for this (Beyond Compare) is the target of the folder, picture and table comparisons below. **Reuse first**: `mdiff` has the folder comparison, the patch writer and the limits for huge diffs (`docs/ASSOCIATED-PROJECTS.md`).

- [ ] **Compare two folders** (priority Next, size M): a tab with the **list of every added, deleted, modified and same file** (counts, filters, a search, a tree or flat view), a **diff** of a text file on a click, **ignores** (`.gitignore`, names, whitespace, line endings, dates), a comparison **by content or by size and date** (a first fast pass by size and date, then a hash only where needed), **copy to the left or to the right** (through the safe operations, with the Local History) and an **export as a patch**; each side is a root, a folder or a ZIP; a budget on two trees of 100,000 files
- [ ] **Large text diffs** (priority Next, size S): the thresholds of `mdiff` (a diff of more than 5,000 lines shows **only the changes with 3 lines of context** and a **Show full file** toggle; no syntax colours past 20,000 lines of patch), a diff computed in a **worker**, and the **export of a comparison as a `.patch`** (git-style, with the path escaping of `mdiff`'s `patch.ts`)
- [ ] **Compare two pictures** (priority Later, size M): **swipe**, **side by side**, **onion skin** (an opacity slider) and a **difference** view (pixel-wise, with a threshold and a count of the pixels that differ) with synchronised zoom and pan; the pixels are compared in a worker
- [ ] **Compare two PDFs** (priority Later, size M): by **text** (page by page, the diff of the extracted text) and by **appearance** (the difference of the drawn pages), with a list of the pages that changed
- [ ] **Compare two archives** (priority Later, size S once the folder comparison exists): an archive is a folder (ZIP now; tar and 7z later), so it is the folder comparison between two roots, with entries that differ in content, size, date or mode marked
- [ ] **Structured comparison** (priority Later, size M): **JSON and YAML by path** (key order ignored, array items by index or by a chosen key), **CSV by key column** (rows added, removed and changed, cell by cell), **SQLite by schema and by rows** of a table; **hex**: two binaries side by side with the differing bytes marked
- [ ] **A three-way comparison and merge** (priority Maybe, size L): a base and two versions, with the conflicts resolved by hand; and **accept or reject a change** in the text diff (the open item under "Text editing")
- [ ] **Comparison of the unsaved text of a tab** with the file, or with a version of the Local History (see "Safety net"), from the editor's menu
- [ ] **Performance** (the rule at the top): every comparison runs off the interface's thread, streams what it can, shows results **as they come** with a progress and **Stop**, and keeps memory bounded (hashes, not contents; windows of the lists); budgets are measured by tests on synthetic trees and pictures
- [ ] Tests: each comparison on hand-made inputs (a folder pair with every status, a renamed file, a file that is a folder on the other side, binary files, a symbolic link; pictures that differ by one pixel; PDFs that differ by one word; CSVs with the same rows in another order; JSON with keys in another order), and an end-to-end spec per kind
